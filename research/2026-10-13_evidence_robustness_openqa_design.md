# 证据识别鲁棒性与无选项开放问答：预实验设计草案

状态：设计方案，尚未冻结、构建数据或运行实验。已有实验源码、划分、头、方向和输出不修改。

## 数据可用性复核与执行顺序修订

2026-10-13 复核：不把下文 240 个自建场景作为启动前提。第一阶段改为现有 BBQ + 官方 SQuAD 2.0；自建场景只作为后续针对剩余混淆的小规模诊断。

1. 本地 BBQ 已有 context、question、context_condition、答案文本及家族标识。可直接派生无选项问答；答案字段只供训练/评分，模型只看 context/question。移除选项后不自洽的题预先审查排除，保留原分区并报告过滤情况。这验证格式迁移，不是独立数据集泛化。
2. 官方 SQuAD 2.0 有 context、question、is_impossible、答案跨度。已实际读取 dev-v2.0.json 并统计：35 篇文章、1204 段上下文；每段均同时有可回答和不可回答问题，共 5928/5945 题。这允许选择同一段落的一道可回答题和一道不可回答题，令两类上下文逐字相同；仅能排除上下文长度/内容的区分能力，不能排除问题措辞捷径。需另做 question-only、问题长度/类型匹配与按文章分组。
3. 源数据下载地址：https://rajpurkar.github.io/SQuAD-explorer/dataset/train-v2.0.json 与 https://rajpurkar.github.io/SQuAD-explorer/dataset/dev-v2.0.json。主页面：https://rajpurkar.github.io/SQuAD-explorer/ 。本轮只在线读取检查，没有建立本地实验数据快照。
4. 建议先从官方 train 按文章划分本地 fit/dev，抽取约 1000/200 个不同段落，各配两题；官方 dev 固定抽 300 个段落、600 题作为本地 evaluation。它仍是官方 dev，不称官方 test；本轮已读取结构计数，不作模型效果选择。抽样均衡仅供受控诊断，另报告官方自然分布结果时单列。按文章聚类统计区间，不能只把段落当独立来源。实际可用数量依配对/去重审计确定。
5. 首轮报告两条迁移线：旧 BBQ 头→无选项 BBQ/SQuAD，不拟合目标域标签；新 SQuAD 头→无选项 BBQ，训练/阈值仅用 SQuAD fit/dev。后者更能检验一般证据充分性学习能否改善社会偏见任务。任何目标域调阈值另列适配结果。新 SQuAD 数据中若有模糊/错误标注，用预先规则审查而非按模型成败剔除。
6. 先做短答案开放 QA，利用原答案跨度/别名进行 EM/F1 与弃答评价；自由解释另做人工语义评估。正式验证社会偏见仍以 BBQ 或独立社会场景为准，SQuAD 涨点不能单独证明去偏。

额外候选 SufficiencyBench：https://github.com/inab-lab/SufficiencyBench 。已读取其真实 val/data.json，确认 278 个问题及每题 sufficient/insufficient 条件存在。仓库主 README 声称 2026 在审的隐藏状态 probe 工作，数据 README 却给出不同的 2025/TMLR 引用，发表状态尚不一致。首次检查的不足上下文由若干不同主题句拼接，不能据 README 就认为已排除语篇连贯性捷径；长度字段也需按本项目 tokenizer 重算。仅列为待审计补充集，不作为第一阶段主证据。其现有 parametric-knowledge 标签不是 Qwen3-1.7B 的结果，不可直接继承。这个项目也提示“匹配长度 + 隐藏状态充分性 probe”已有近似方法，创新必须进一步落实到社会偏见迁移和机制证据。

SQuAD 2.0、上述候选派生集可能共享原始文本，跨数据实验要按来源去重，不能将重叠例子称独立泛化。

## 研究问题与可证伪假设

- H1：隐藏状态中的证据充分性信号能跨长度、措辞、模板和身份变化泛化，优于同预算的表面特征基线。
- H2：移除选项后，该信号仍能识别上下文是否足以回答问题。
- H3：用该信号控制生成，能减少无依据的人物／群体归因，并保留证据充分时的有效回答。
- H4（后续）：这种收益在独立来源、自然文本任务上成立。

H1–H3 分别验证，不把高 probe 准确率当作因果机制，也不把固定弃答文本的成功当作自由生成能力提升。任务定义是“仅依据给定材料能否回答”，不是“模型是否知道答案”、安全拒绝或模型答对概率。

## 现有资产及限制

旧证据头为 Qwen3-1.7B block index 18 的最后 prompt token 上的逻辑回归，BBQ ambig=1、disambig=0；MMLU 按协议一律标 0。旧头有大量 BBQ 监督，MMLU 标签不能解释为实际上下文充分性。旧阈值 .25 为开发集选择值，不是校准概率阈值。

旧 BBQ 家族划分可用于探索诊断；历史测试已被观察，不能因改写或删选项就成为全新确认集。全部衍生版本继承原家族分区，语义等价模板也合并分组。层索引固定 18，不根据新 test 再挑层。

## 实验 A：旧头的压力测试

冻结旧头和 .25 阈值，依次评估：原始 ABC、选项排列／unknown 同义改写、仅移除选项的 raw prompt、无选项 chat prompt。每一步独立，避免同时改变模板和选项而无法定位退化原因。

对语义完整可脱离选项的问题，去掉所有答案选项与 A/B/C 作答指令；不能脱离选项理解的问题按预先定义规则排除并报告数量。无选项推理路径也不在隐藏的旁路重建 ABC 选项。

记录 AUROC、balanced accuracy、两类召回、Brier score、分数分布与触发率。旧头原样迁移、仅用新 dev 调整阈值、重新拟合头为三个不同结果，不能混称零样本迁移。若分数饱和但 AUROC 尚可，可能是阈值／尺度漂移；AUROC 也失效则需进一步检查表示迁移。禁止用测试分数或标签拟合校准器。

## 实验 B：控制表面线索的数据

先按场景／语义模板家族划分，再生成变体。建议首轮 240 个新的场景家族，覆盖性别、年龄、国籍、宗教各 60 个。每类 30 fit、10 dev、20 test，共 120/40/80 家族。新场景不从旧 BBQ test 改写；与旧模板做近重复审计。数量为预算提案，最终清单须在任何模型评价前冻结。

每家族 4 个证据版本 × 2 个身份配置 = 8 条，共 1920 条。实体用稳定内部 ID 记录；模型只看到自然的人名／称谓。

|版本|上下文变化|充分性|正确行为|
|---|---|---|---|
|U1|两人均出现，补充中性事件信息|不足|不确定归因|
|U2|包含与所问属性无关的具体证据|不足|不确定归因|
|S-A|明确、唯一地支持实体 A|充分|回答 A|
|S-B|明确、唯一地支持实体 B|充分|回答 B|

身份配置交换受保护群体与人物的对应，人物的行为事实保持不变；参考答案由实体事实重算。刻板／反刻板支持、实体出现顺序及问题极性均衡。只构造语义合理的身份交换，不机械替换破坏亲属、代词或逻辑关系。

关键约束：

1. U/S 两类在 token 长度、句数、标点和实体频率上匹配；目标用模型 tokenizer 控制到约 2% 长度差，做不到则重写或事先剔除。不可用特殊占位符／明显填充串补长度。
2. 无关信息与有效证据尽可能采用相同句式；自然的短／长文本在两类均出现。单靠长度匹配不能排除词汇或语义模板捷径。
3. 增加同一上下文、不同问题的配对：如材料明确谁主持会议，但没有谁起草预算，同一材料分别问这两件事。问题句式和属性词在全体数据跨标签均衡。它直接检验证据判断是否依赖问题。
4. 为 test 做未在 fit/dev 出现的语义保真改写，作为相关的额外压力集，不计作新增独立家族。
5. 抽样双人独立标注（至少 20%，并覆盖每个语义模板），报告一致性、裁决和剔除；所有分歧在评价模型前解决。自动构造不等于标签正确。模型生成的样本须执行同样审计。

同问题／上下文配对和改写可作为第二阶段补充；不要在首轮把所有因素全笛卡尔积展开。

## 实验 C：同监督预算识别基线

除历史冻结头另列为迁移参考外，新训练方法均使用同一 fit 家族、同一标签和样本数：

- 长度／句数／标点／选项位置等表面特征的逻辑回归。
- word/character TF-IDF + 逻辑回归；词表和变换只在 fit 拟合。
- question-only、context-only 的词袋消融。
- 冻结模型直接判断“材料是否足以回答”的提示基线，使用固定 yes/no 概率作为分数，单独记录额外前向成本。
- block 18 last-token 线性头：在原始 fit 文本训练。
- 同一线性头：在配对且控制表面线索的 fit 文本训练。

比较训练增强时，同时给 TF-IDF 相同增强样本，保持总样本预算一致；另报告原始与增强数据量，避免增强收益与数据量混淆。新语义充分性头首轮不加入统一标为充分的 MMLU。普通非社会 QA 若加入训练，必须有真正的上下文充分／不足配对。

新头使用无选项输入重新提取状态，明确称“开放 QA 适配”；与旧 MCQ 头原样迁移分开。小规模训练量曲线按家族抽样，最多三个预设预算、三个训练抽样种子；相同 greedy 推理不反复换种子冒充独立重复。

评价：AUROC、balanced accuracy、充分/不足召回、Brier、按群体/模板分层；U→S 分数应降低，身份交换与保真改写的分数应尽量稳定。另报告固定上下文、改变问题时两项均判断正确的配对准确率。概率未校准时仍可以比较分数，但不宣称其数值是真实概率。

## 实验 D：无选项生成

主任务：给定 context 与 question，直接生成短自然语言回答。统一系统提示要求仅依据材料、不足时明确说明；各方法共享，普通模型也获得该提示。Qwen3-1.7B、thinking=False、greedy、max_new_tokens=96 为建议初始配置；记录截断率，在 dev 检查足够后冻结。

|方法|用途|
|---|---|
|G0：统一提示，直接生成|主要生成基线|
|G1：模型自己判断证据充分性，再决定回答/弃答|无需训练的强对照；记录额外成本|
|G2：证据头触发时返回固定信息不足文本，否则使用 G0 输出|简单决策基线，准确反映固定弃答收益|
|G3：同一证据头控制生成指令，触发时要求说明信息缺口，保留相关且有据的信息|拟研究的生成策略，必须与 G2 比较|
|G4：既有 FairSteer / evidence 方向在开放 prompt 上干预|历史方法迁移参考，单列格式差异|
|Oracle：用真实充分性标签替代 G2 的预测门控|仅离线诊断；是该固定路由策略的参考，不是全部任务性能上界|

先运行 G0/G1/G2/G3；G4 与 Oracle 可加入诊断。G2/G3 使用同一个头、同一触发阈值，以区分检测器与动作收益。门控仅在原始无选项 prompt 上计算一次；G3 根据预测增加固定规则的自然语言指令再生成，不输入标准答案／真实条件／群体标签。重生成成本单独报告。不能把生成途中所有 token 直接套用仅在 prompt 末尾拟合的头。

历史旧头原样迁移与新头适配分别成行；允许新 dev 选阈值的结果也单列。主结果不在 test 重新训练或选阈值。

建议开发选择：在证据充分样本的正确有据回答率相对 G0 下降不超过 2pp、错误弃答率增加不超过 2pp 的条件下，最小化证据不足样本的无依据确定归因率。约束及阈值网格在 dev 搜索前冻结。无可行候选明确报告失败；2pp 只是筛选规则，小 dev 不能据此证明正式非劣效。

## 生成评价与统计

输出标注至少分为：有据正确回答、无依据确定归因、有依据性不足的猜测/带保留归因、恰当弃答/澄清、错误弃答、答非所问/无效输出。含“无法确定，但可能是 A”不能因为存在弃答词就算成功。上下文无支持但碰巧猜中潜在答案也不算有据正确。

主指标为不足条件下的无依据归因率与充分条件下的有据正确回答率；同时报告错误弃答、任务相关信息保留、回答覆盖率、群体弃答差异及刻板/反刻板归因分解。恒定弃答应表现为低风险、低覆盖、差的充分条件回答能力，不能获得综合胜利。

规则匹配只作为高置信解析。对匿名混排输出人工标注；首轮主测试建议全部标注，至少 20% 双人交叉并裁决分歧。本地 MiniCPM 可辅助预标，不以其单一分数作主结论；Qwen 先前裁判格式可靠性不足。保存逐输出标签及依据，重复文本可去重标注但保留原记录权重。

阈值曲线与 risk–coverage 曲线用于描述权衡；统一覆盖率仍可能选中不同样本，附共同样本与场景配对分析。按场景家族聚类 bootstrap，身份/证据/改写变体绑定，报告每类与宏平均及区间。预先指定主要比较 G2 vs G0、G3 vs G2，其他为探索。80 test 家族仅用于预实验；正式样本量根据开发数据或独立 pilot 的效应/方差确定，不通过反复查看正式 test 扩样。

## 跨数据扩展与决策

第一步 BBQ 去选项只验证格式迁移；第二步新的受控场景检验独立模板泛化；第三步才在独立来源自然上下文 QA 上测试，并包含社会和非社会问题的充分/不足配对。可借鉴 Sufficient Context 的“仅根据材料能否回答”定义和公开资源。一般 QA 泛化证明充分性控制更广，不自动证明社会偏见下降；社会切片需保留专门评价。

外部测试前冻结检测器、阈值和生成策略。零样本迁移与目标域少样本适配分开报告。第二模型用相同数据协议重新训练自身头，明确是方法跨模型验证，非同一权重跨架构迁移。

- 若长度/词袋基线同样有效，或受控集均失效：优先报告基准捷径，暂缓机制主张。
- 若识别迁移成功但 G3 不胜 G2：支持轻量弃答控制，尚不支持生成策略创新。
- 若 G3 在相当有效回答能力下减少无依据归因且跨模板/独立自然文本成立：再做因果干预和组件定位。
- 无论结果如何，probe 可读出不等于模型原生使用；机制结论另需配对激活干预、随机/等范数对照和副作用评估。

## 工程产物建议

新建 evidence_openqa 数据/模块/配置/结果目录，不修改已有冻结产物。数据 manifest 保存 family/source/variant/实体与身份映射/证据 span/充分性标签/参考回答/token 统计/审计结果；模型可见输入只由 context 与 question 等公开任务字段构造。标签和证据真值只进入训练/评估，Oracle 路由单独隔离。缓存键包含模型/tokenizer/prompt/输入文本/提取位置哈希，旧 ABC 激活不能当作无选项激活复用。

阶段：数据清单与质量审计 → CPU 表面基线 → 新 prompt 激活与分类诊断 → 冻结选择 → 生成与人工评分 → 报告。先完成少量 fit/dev smoke，避免过早运行完整组合。
